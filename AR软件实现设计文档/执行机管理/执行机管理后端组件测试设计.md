## 2. 核心集成测试场景

### 2.1 Agent注册认证流程（IT-01）

**测试目标**：验证四阶段CHAP认证流程，适配V4的JSON协议和Base64/Hex编码

**输入数据**：
- **Register-Request消息**：
  - 格式: JSON Text Message
  - JSON信封: `{"type": "RegisterRequest", "payload": {...}}`
  - Payload字段: `hostname` (字符串)

- **认证凭据**：
  - Username: 测试用户名称（从dial_users表）
  - NTLM Hash: 32字符十六进制字符串

**测试步骤**：
1. 建立WebSocket连接到执行机管理服务 (`wss://server:port/ws/executor`)
2. 构造并发送Register-Request消息（JSON Text格式）：
   ```json
   {
     "type": "RegisterRequest",
     "payload": {
       "hostname": "test-executor-01"
     }
   }
   ```
3. 接收并验证Register-Challenge消息（JSON Text格式）：
   - 验证JSON信封结构（type、payload）
   - 从payload提取 `challenge-id` (int) 和 `challenge` (Base64字符串)
   - 解码Base64得到16字节随机数
4. 计算MD5响应：
   - 从数据库获取测试用户的NTLM Hash
   - 计算：`MD5(NTLM_Hash + Challenge)`
   - 将结果编码为Hex字符串
5. 构造并发送Register-Response消息（JSON Text格式）：
   ```json
   {
     "type": "RegisterResponse",
     "payload": {
       "challenge-id": 123,
       "username": "test-user",
       "response": "a1b2c3d4e5f6..."
     }
   }
   ```
6. 接收并验证Register-Result消息（JSON Text格式）：
   - 验证 `result` = 0（成功）
   - 提取 `token`（8字节整数）
   - 保存token用于后续消息
7. 查询数据库验证执行机状态：
   - `executor.status` = 1 (ONLINE)
   - `executor.token` = 收到的token值
   - `executor.last_online_time` 为当前时间

**输出验证**：
- **Register-Challenge消息**：
  ```json
  {
    "type": "RegisterChallenge",
    "payload": {
      "challenge-id": 123,
      "challenge": "YWJjZGVmZ2hpamtsbW5vcA=="  // Base64编码的16字节
    }
  }
  ```

- **Register-Result消息**：
  ```json
  {
    "type": "RegisterResult",
    "payload": {
      "result": 0,
      "description": "Authentication successful",
      "token": 1234567890123456
    }
  }
  ```

- **数据库状态**：
  - `executor.status`: 1 (ONLINE)
  - `executor.token`: 1234567890123456
  - `executor.last_online_time`: 当前时间戳

**验证要点**：
- JSON消息格式正确（信封结构、payload结构）
- 四阶段握手流程完整（Request→Challenge→Response→Result）
- Base64编码/解码正确（challenge字段）
- Hex编码正确（response字段）
- MD5摘要算法正确实现
- 数据库状态正确更新
- 会话绑定关系建立

### 2.3 任务下发执行流程（IT-03）⚠️ 重点测试

**测试目标**：验证JSON信令 + Binary分片混合模式的任务流程

**输入数据**：
- **TaskStart-Request消息（服务端→Agent）**：
  - 格式: JSON Text Message
  - 字段: `token`, `taskid`, `script-name`, `version`, `serial-no` (数组), `proctype`, `parameters`

- **TaskStart-Response消息（Agent→服务端）**：
  - 格式: JSON Text Message（仅元数据，不含文件）
  - 字段: `token`, `taskid`, `result`, `block`, `description`, `sub-result` (数组), `filelen`, `crc`

- **日志文件分片（Agent→服务端）**：
  - 格式: Binary Message（多个）
  - 内容: 原始二进制数据，无信封

**测试步骤**：
1. 基于IT-01完成认证，保持WebSocket连接
2. 通过业务层模拟下发任务（调用TaskInterfaceService.dispatchTaskToAgent()）
3. Agent接收并验证TaskStart-Request消息（JSON Text）：
   ```json
   {
     "type": "TaskStartRequest",
     "token": 1234567890123456,
     "payload": {
       "token": 1234567890123456,
       "taskid": 100001,
       "script-name": "test-script",
       "version": "1.0.0",
       "serial-no": ["ABC123456"],
       "proctype": 1,
       "parameters": "{\"key\":\"value\"}"
     }
   }
   ```
4. 模拟Agent执行任务，准备日志文件和执行结果
5. **第一步：发送JSON信令**，Agent发送TaskStart-Response消息（仅包含元数据）：
   ```json
   {
     "type": "TaskStartResponse",
     "token": 1234567890123456,
     "payload": {
       "token": 1234567890123456,
       "taskid": 100001,
       "result": "Success",
       "block": "",
       "description": "Task completed successfully",
       "sub-result": [
         {
           "serial": "ABC123456",
           "result": "Success",
           "description": "OK"
         }
       ],
       "filelen": 1048576,
       "crc": "a1b2c3d4"
     }
   }
   ```
6. **第二步：连续发送Binary分片**，Agent立即发送N个Binary Message（日志文件分片）：
   - 每个分片为纯二进制数据（无JSON信封）
   - 分片大小建议100KB
   - 所有分片总大小必须等于JSON信令中的 `filelen`
7. 服务端验证：
   - 业务层通过 `handleTaskStartResponse` 接收JSON信令
   - 通信层 `InboundFileHandler` 接收所有Binary分片
   - 计算接收文件的CRC32，与JSON信令中的 `crc` 比对
8. 验证异步回调：
   - 文件接收完成后，`InboundFileCompleteCallback.onInboundFileComplete` 被调用
   - 业务层从回调中获取临时文件路径
   - 业务层将文件存储到最终位置并生成URL
9. 验证上层通知：
   - 任务管理模块收到任务完成通知
   - 通知包含 `sub-result` 和 `fileUrl`

**输出验证**：
- **JSON信令到达时机**：在所有Binary分片之前
- **Binary分片特征**：
  - 每个分片为Raw Binary数据
  - 无JSON信封或头部结构
  - 必须紧跟JSON信令连续发送
- **文件完整性**：
  - 所有分片拼接后的总大小 = `filelen`
  - CRC32校验值 = `crc`
- **异步回调验证**：
  - `onInboundFileComplete` 被正确调用
  - `InboundFileState` 包含正确的 `tempFilePath`、`filelen`、`crc`、`taskId`
- **文件存储验证**：
  - 临时文件成功移动到最终存储位置
  - 生成可访问的文件URL
  - 原临时文件被清理

**验证要点**：
- JSON信令与Binary分片完全分离
- 发送顺序正确（JSON先，Binary后）
- Binary分片为纯二进制流（无信封）
- 文件分片接收和拼接正确
- CRC32校验通过
- 异步回调机制正确（InboundFileCompleteCallback）
- 跨层通知机制正确（业务层→任务管理层）
- 错误处理：分片丢失、CRC校验失败、超时等

### 2.4 离线处理和重连流程（IT-04）

**测试目标**：验证连接断开处理、状态清理和重连恢复

**输入数据**：
- **初始状态**：
  - `executor.status`: 1 (ONLINE)
  - 有效的WebSocket连接和会话绑定
  - 已生成的token

- **断开触发**：
  - 主动关闭WebSocket连接
  - 或等待心跳超时（90秒）

**测试步骤**：
1. 基于IT-01完成认证，建立心跳
2. **场景A：主动断开**
   - Agent主动断开WebSocket连接
   - 立即验证服务端状态更新
3. **场景B：心跳超时**
   - 停止发送Report-Msg消息
   - 等待90秒（3个心跳周期）
   - 验证服务端超时检测触发
4. 验证离线状态：
   - 查询数据库：`executor.status` = 0 (OFFLINE)
   - 验证会话绑定被清理（SessionBindingRegistry）
   - 验证token失效
5. **重连测试**：
   - 重新建立WebSocket连接
   - 尝试使用旧token发送消息（应失败）
   - 重新执行完整的四阶段认证流程（IT-01）
   - 验证新token生成，状态恢复为ONLINE
6. 验证重连后状态：
   - `executor.status` = 1 (ONLINE)
   - `executor.token` = 新的token值（与旧token不同）
   - 新的会话绑定建立

**输出验证**：
- **连接断开后状态**：
  - `executor.status`: 0 (OFFLINE)
  - 会话绑定关系被清理
  - token失效（数据库可能清空或标记失效）

- **重连认证结果**：
  - 必须重新执行四阶段认证（不能使用旧token）
  - Register-Result消息: `result`=0, 新token生成
  - `executor.status`: 1 (ONLINE)
  - `executor.token`: 新的8字节令牌（与旧token不同）
  - 会话重新绑定

**验证要点**：
- 连接断开时状态正确更新为OFFLINE
- 会话绑定关系及时清理
- 心跳超时检测机制正确（90秒）
- 重连时强制重新认证（不能使用旧token）
- 新认证成功后生成新的token
- 状态恢复机制可靠
- 历史记录保持完整

```python
class JsonMessageHandler:
    def encode(self, message_type: str, token: int, payload: dict) -> str:
        """编码JSON消息"""
        envelope = {
            "type": message_type,
            "token": token,
            "payload": payload
        }
        return json.dumps(envelope)
    
    def decode(self, json_str: str) -> dict:
        """解码JSON消息"""
        envelope = json.loads(json_str)
        return {
            "type": envelope["type"],
            "token": envelope.get("token"),
            "payload": envelope["payload"]
        }
```

**3. Base64/Hex编解码器**：
```python
import base64
import binascii

class BinaryFieldEncoder:
    @staticmethod
    def encode_base64(data: bytes) -> str:
        """Base64编码（用于challenge）"""
        return base64.b64encode(data).decode('ascii')
    
    @staticmethod
    def decode_base64(data: str) -> bytes:
        """Base64解码"""
        return base64.b64decode(data.encode('ascii'))
    
    @staticmethod
    def encode_hex(data: bytes) -> str:
        """Hex编码（用于response、crc）"""
        return binascii.hexlify(data).decode('ascii')
    
    @staticmethod
    def decode_hex(data: str) -> bytes:
        """Hex解码"""
        return binascii.unhexlify(data.encode('ascii'))
```

**4. CRC32计算器**：
```python
import zlib

class CrcCalculator:
    @staticmethod
    def calculate(data: bytes) -> str:
        """计算CRC32并返回Hex字符串"""
        crc = zlib.crc32(data) & 0xffffffff
        return format(crc, '08x')
    
    @staticmethod
    def verify(data: bytes, expected_crc: str) -> bool:
        """验证CRC32"""
        actual_crc = CrcCalculator.calculate(data)
        return actual_crc.lower() == expected_crc.lower()
```

**5. Binary分片处理器**：
```python
class BinaryChunkHandler:
    CHUNK_SIZE = 102400  # 100KB per chunk
    
    @staticmethod
    def split_file(file_path: str) -> list:
        """将文件拆分为分片"""
        chunks = []
        with open(file_path, 'rb') as f:
            while True:
                chunk = f.read(BinaryChunkHandler.CHUNK_SIZE)
                if not chunk:
                    break
                chunks.append(chunk)
        return chunks
    
    @staticmethod
    def assemble_chunks(chunks: list) -> bytes:
        """将分片拼接为完整文件"""
        return b''.join(chunks)
```
