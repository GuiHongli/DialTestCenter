# 执行机管理后端组件测试设计

## 1. 概述

本文档定义了执行机管理组件的功能测试用例，覆盖 WebSocket 通信、认证与会话、执行机状态管理、任务通道、北向 API 等核心功能。

### 1.1 测试范围

- **WebSocket通信**：连接建立、消息收发、断开处理
- **认证与会话**：CHAP 四阶段注册、会话管理、注销
- **执行机管理**：心跳处理、状态更新、离线处理
- **任务通道**：任务下发、状态上报
- **北向API**：执行机列表查询、信息刷新

### 1.2 测试工具

| 工具 | 用途 |
|------|------|
| Python + websocket-client | 模拟执行机客户端 |
| requests | REST API测试 |
| psycopg2 | 数据库状态验证 |

## 2. 核心测试场景

### 2.1 场景 SC-01：Agent 注册与认证（CHAP 四阶段）

**场景描述：** Agent 通过 WebSocket 发起注册请求，完成 CHAP 四阶段认证，服务端返回 token 并建立会话。

#### TC-01-001：成功注册

**步骤1：** Agent 发送注册请求
```json
{
  "message_type": "register_request",
  "data": {
    "name": "Executor_PC_001",
    "username": "agent_user",
    "ne_name": "EPSN_614"
  }
}
```

**步骤2：** 服务端返回 Challenge
```json
{
  "message_type": "register_challenge",
  "data": {
    "challenge": "YWJjZGVmZ2hpamtsbW5vcA=="
  }
}
```

**步骤3：** Agent 发送认证响应（MD5(NTLM_Hash + Challenge)）
```json
{
  "message_type": "register_auth",
  "data": {
    "response": "5f4dcc3b5aa765d61d8327deb882cf99"
  }
}
```

**步骤4：** 服务端返回注册成功
```json
{
  "message_type": "register_ack",
  "data": {
    "status": "success",
    "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
    "error_message": ""
  }
}
```

**验证要点：**
- Challenge 长度为 16 字节（Base64 编码后 24 字符）
- Token 非空且与会话绑定
- 数据库：`executor.status=1`（ONLINE），`executor.token` 已更新

---

#### TC-01-002：用户名不存在

**输入数据：**
```json
{
  "message_type": "register_request",
  "data": {
    "name": "Executor_PC_001",
    "username": "__not_exists__",
    "ne_name": "NE_TEST"
  }
}
```

**期望输出：**（在认证响应阶段）
```json
{
  "message_type": "register_ack",
  "data": {
    "status": "failed",
    "token": "",
    "error_message": "User not found"
  }
}
```

**验证要点：**
- 服务端仍返回 Challenge（避免用户名枚举）
- 最终认证失败，不下发 token
- 数据库不更新为 ONLINE 状态

---

#### TC-01-003：响应摘要不匹配

**输入数据：** 正确用户名，但在步骤3发送错误的 response 值

**期望输出：**
```json
{
  "message_type": "register_ack",
  "data": {
    "status": "failed",
    "token": "",
    "error_message": "AUTH_FAILED"
  }
}
```

**验证要点：**
- 不绑定会话
- 可重新发起注册

---

#### TC-01-004：注销（deregister）

**输入数据：**
```json
{
  "message_type": "deregister",
  "data": {
    "name": "Executor_PC_001"
  }
}
```

**验证要点：**
- 数据库：`executor.status=0`（OFFLINE）
- 会话解除绑定
- 后续心跳需重新注册

---

### 2.2 场景 SC-02：心跳与状态维护

**场景描述：** 认证成功后，Agent 周期性发送心跳，服务端更新执行机在线状态与 UE 列表。

#### TC-02-001：心跳更新状态

**输入数据：**
```json
{
  "message_type": "heartbeat_status",
  "data": {
    "timestamp": 1699518400,
    "ue_list": [
      {
        "msisdn": "86138****0001",
        "serial": "SN001",
        "status": "idle",
        "vendor": "Huawei",
        "model": "P60",
        "os_version": "Android 13",
        "ip_v4": "192.168.1.10",
        "battery_level": 85
      },
      {
        "msisdn": "86139****0002",
        "serial": "SN002",
        "status": "busy",
        "vendor": "Xiaomi",
        "model": "Mi 13",
        "os_version": "Android 12"
      }
    ]
  }
}
```

**验证要点：**
- 数据库：`executor.status=1`（ONLINE），`last_online_time` 已更新
- 数据库：`ue` 表中两条记录已创建或更新
- UE 详细信息（vendor、model、os_version等）正确入库

---

#### TC-02-002：UE 清单变更

**测试步骤：**
1. 第一次心跳发送 3 个 UE（SN001、SN002、SN003）
2. 第二次心跳发送 3 个 UE（SN001、SN002修改状态、SN004新增）

**验证要点：**
- SN001 保持不变
- SN002 状态已更新
- SN003 按策略处理（保留或标记删除）
- SN004 已新增

---

#### TC-02-003：离线处理

**测试步骤：**
1. Agent 完成注册并发送心跳
2. 关闭 WebSocket 连接

**验证要点：**
- 数据库：`executor.status=0`（OFFLINE）
- 会话映射已移除
- 重新连接需重新注册

---

### 2.3 场景 SC-03：北向 API

**场景描述：** 管理员通过 REST API 查询执行机列表或触发信息刷新。

#### TC-03-001：查询执行机列表

**请求示例：**
```
GET /api/v1/executors?page=0&size=20
```

**响应示例：**
```json
{
  "content": [
    {
      "name": "Executor_PC_001",
      "ip": "10.0.0.10",
      "status": 1,
      "lastOnlineTime": "2025-11-09T10:30:00Z",
      "ueCount": 2,
      "description": "测试执行机"
    }
  ],
  "totalElements": 1,
  "totalPages": 1,
  "size": 20,
  "number": 0
}
```

**验证要点：**
- HTTP 状态码 200
- 响应包含 `content` 数组和分页信息
- 执行机信息字段完整（name、ip、status、lastOnlineTime）
- 不返回敏感信息（token 原文）

---

#### TC-03-002：刷新执行机信息

**请求示例：**
```
POST /api/v1/executors/refresh
Content-Type: application/json

{
  "executorName": "Executor_PC_001"
}
```

**响应示例：**
```json
{
  "code": 200,
  "message": "Refresh request sent",
  "data": null
}
```

**验证要点：**
- HTTP 状态码 200 或 202
- 服务端向目标会话发送 `update_executor_info` 消息
- Agent 回复 `executor_info_response` 后数据库已更新

### 2.4 场景 SC-04：任务通道

**场景描述：** 上层模块通过任务接口服务下发任务，Agent 执行后上报状态。

#### TC-04-001：任务下发

**下行消息示例：**
```json
{
  "message_type": "task_assign",
  "data": {
    "task_id": "T_20251109_001",
    "ue_serial": "SN001",
    "launcher": "airtest_launcher.py",
    "script_name": "douyin_openlive.air",
    "script_version": "1.1",
    "params": {
      "timeout": 300,
      "target_app": "com.ss.android.ugc.aweme"
    }
  }
}
```

**验证要点：**
- 消息仅发送给指定执行机的会话
- `script_version` 字段正确传递
- Agent 成功接收消息

---

#### TC-04-002：任务状态上报

**上行消息示例：**
```json
{
  "message_type": "task_status_update",
  "data": {
    "task_id": "T_20251109_001",
    "status": "success",
    "result_code": 0,
    "message": "执行完毕",
    "log_path": "s3://bucket/logs/T_20251109_001.log",
    "annotations": [
      {
        "timestamp": 1699518500,
        "label": "login_success"
      }
    ]
  }
}
```

**验证要点：**
- 服务端接收到上报消息
- 任务接口服务将状态转发至上层模块
- 字段完整性校验通过

### 2.5 场景 SC-05：环境管理

**场景描述：** 服务端通知 Agent 更新脚本或安装应用。

#### TC-05-001：脚本更新通知

**下行消息示例：**
```json
{
  "message_type": "script_update_notify",
  "data": {
    "package_name": "openlive_scripts",
    "version": "1.1",
    "package_url": "s3://bucket/scripts/openlive_v1.1.zip",
    "checksum": "5d41402abc4b2a76b9719d911017c592"
  }
}
```

**上行回执示例：**
```json
{
  "message_type": "script_update_ack",
  "data": {
    "package_name": "openlive_scripts",
    "version": "1.1",
    "status": "success",
    "message": "脚本更新成功"
  }
}
```

**验证要点：**
- 下发消息字段完整（package_url、checksum）
- Agent 回执被记录

---

#### TC-05-002：应用安装

**下行消息示例（URL方式）：**
```json
{
  "message_type": "app_install",
  "data": {
    "ue_serial": "SN001",
    "install_type": "url",
    "app_url": "https://example.com/app.apk",
    "package_name": "com.example.app"
  }
}
```

**下行消息示例（脚本方式）：**
```json
{
  "message_type": "app_install",
  "data": {
    "ue_serial": "SN001",
    "install_type": "script",
    "script_name": "install_wechat.air",
    "package_name": "com.tencent.mm"
  }
}
```

**上行回执示例：**
```json
{
  "message_type": "app_install_result",
  "data": {
    "ue_serial": "SN001",
    "package_name": "com.example.app",
    "status": "success",
    "message": "应用安装成功"
  }
}
```

**验证要点：**
- 不同 `install_type` 的必填字段校验
- 安装结果被记录
