## 2. 核心集成测试场景

### 2.1 Agent注册认证流程（IT-01）

**测试目标**：验证四阶段CHAP认证流程的完整执行，包括业务层与通信层的交互

**输入数据**：
- **Register-Request消息**：
  - Message Type: 0x01
  - Fields: executor_name (字符串), username (字符串)

- **认证凭据**：
  - Username: 测试用户名称
  - NTLM Hash: 32字符十六进制字符串

**测试步骤**：
1. 建立WebSocket连接到执行机管理服务
2. 发送TLV格式的Register-Request消息（包含executor_name和username）
3. 验证收到Register-Challenge消息（包含16字节随机challenge）
4. 计算MD5响应（MD5(NTLM_Hash + Challenge)）并发送Register-Response消息
5. 验证收到Register-Result消息（result=0表示成功，包含8字节token）
6. 查询数据库验证执行机状态更新为ONLINE，token字段已设置

**输出验证**：
- **Register-Challenge消息**：
  - Message Type: 0x02
  - Fields: challenge (16字节随机数)

- **Register-Result消息**：
  - Message Type: 0x04
  - Fields: result (0=成功), token (8字节会话令牌)

- **数据库状态**：
  - executor.status: 1 (ONLINE)
  - executor.token: 8字节令牌值
  - executor.last_online_time: 当前时间戳

**验证要点**：
- TLV消息格式正确（消息头Type+Length，字段Tag+Length+Value）
- 四阶段握手流程完整（Request→Challenge→Response→Result）
- MD5摘要算法正确实现
- 数据库状态正确更新（status=1，token，last_online_time）
- 会话绑定关系建立

### 2.2 心跳状态维护流程（IT-02）

**测试目标**：验证心跳机制和UE信息批量更新的正确性

**输入数据**：
- **Report-Msg消息**：
  - Message Type: 0x11
  - Fields: token (8字节), state (1=ONLINE), ue_list (UE设备数组)

- **UE设备信息**：
  - msisdn: 手机号 (15位字符串)
  - serial: 设备序列号 (字符串)
  - vendor: 制造商 (字符串)
  - model: 型号 (字符串)
  - os_version: 操作系统版本 (字符串)

**测试步骤**：
1. 基于IT-01完成认证，建立WebSocket连接
2. 构造UE设备列表（包含msisdn、vendor、model、os_version等信息）
3. 发送Report-Msg消息（包含token、state=1、ue_list）
4. 验证收到Report-Ack确认消息
5. 查询数据库验证last_online_time更新为当前时间
6. 验证UE信息正确插入/更新到ue表（JSON格式存储）
7. 重复步骤2-6，验证连续心跳保持状态

**输出验证**：
- **Report-Ack消息**：
  - Message Type: 0x12
  - Fields: result (0=成功)

- **数据库状态**：
  - executor.last_online_time: 更新为最新时间戳
  - ue表记录: 为每个UE设备创建/更新记录
  - ue.info: 以JSON格式存储设备详细信息

**验证要点**：
- Report-Msg消息格式正确（消息ID 0x11）
- UE列表以TLV容器格式编码传输
- 批量UE更新操作成功（insert/update）
- 时间戳字段正确更新
- 状态保持机制正常（30秒周期）

### 2.3 任务下发执行流程（IT-03）

**测试目标**：验证任务分发、执行、结果上报的完整流程

**输入数据**：
- **TaskStart-Request消息**：
  - Message Type: 0x33
  - Fields: task_id (字符串), script_name (字符串), version (字符串), serial_no_list (字符串数组), proctype (字符串), parameters (JSON字符串)

- **任务参数**：
  - task_id: 任务唯一标识符
  - script_name: 拨测脚本名称
  - version: 脚本版本号
  - serial_no_list: UE设备序列号列表
  - proctype: 处理类型
  - parameters: 脚本执行参数

**测试步骤**：
1. 基于IT-01完成认证，保持WebSocket连接
2. 通过业务层TaskInterfaceService.dispatchTaskToAgent()下发任务
3. 验证Agent通过WebSocket收到TaskStart-Request消息
4. 模拟Agent执行任务，构造执行结果
5. 发送TaskStart-Response消息（包含result、sub-result、files等）
6. 验证业务层正确解析结果并存储日志文件
7. 验证上层任务管理模块收到执行结果通知

**输出验证**：
- **TaskStart-Response消息**：
  - Message Type: 0x34
  - Fields: task_id, result (0=成功), block (阻塞信息), sub_result (各UE结果数组), files (日志文件二进制数据), crc (校验码)

- **任务结果数据**：
  - result: 总体执行结果 (0=成功, 其他=失败)
  - sub_result: 各UE设备的独立执行结果
  - files: 压缩的日志文件数据
  - crc: 文件校验码

- **文件存储**：
  - 日志文件保存到指定存储位置
  - 生成可访问的文件URL
  - CRC校验通过

**验证要点**：
- 任务参数完整传递（scriptName、version、serialNoList、proctype、parameters）
- TaskStart-Request/Response消息格式正确
- 文件上传和存储机制正常
- 跨层通知机制正确（业务层→任务管理层）
- 错误处理和异常情况覆盖

### 2.4 离线处理和重连流程（IT-04）

**测试目标**：验证连接断开处理、状态清理和重连恢复

**输入数据**：
- **初始状态**：
  - executor.status: 1 (ONLINE)
  - 有效的WebSocket连接和会话绑定
  - 已生成的token

- **断开触发**：
  - 主动关闭WebSocket连接
  - 或等待心跳超时（90秒）

**测试步骤**：
1. 基于IT-01完成认证，建立心跳
2. 主动断开WebSocket连接
3. 等待心跳超时（90秒）或立即验证状态更新
4. 确认数据库中执行机状态变为OFFLINE
5. 重新建立WebSocket连接
6. 重新执行完整的四阶段认证流程
7. 验证新token生成，状态恢复为ONLINE

**输出验证**：
- **连接断开后状态**：
  - executor.status: 0 (OFFLINE)
  - 会话绑定关系被清理
  - token失效

- **重连认证结果**：
  - Register-Result消息: result=0, 新token生成
  - executor.status: 1 (ONLINE)
  - executor.token: 新的8字节令牌
  - 会话重新绑定

- **数据库状态**：
  - 离线状态正确记录
  - 重连后状态恢复
  - 历史记录保持完整

**验证要点**：
- 连接断开时状态正确更新为OFFLINE
- 会话绑定关系及时清理
- 重连时强制重新认证（不能使用旧token）
- 新认证成功后生成新的token
- 状态恢复机制可靠

### 2.5 UE应用管理流程（IT-05）

**测试目标**：验证App列表查询、应用安装、截屏获取等UE应用管理功能

**输入数据**：
- **AppList-Query消息**：
  - Message Type: 0x21
  - Fields: serial_no (UE设备序列号)

- **AppInstall-Request消息**：
  - Message Type: 0x23
  - Fields: serial_no, task_id, app_name, package/script数据

**测试步骤**：
1. 基于IT-01完成认证，保持WebSocket连接
2. 发送AppList-Query消息查询指定UE的应用列表
3. 验证收到AppList-Response消息包含应用列表
4. 发送AppInstall-Request消息请求安装应用
5. 验证收到AppInstall-Response消息确认安装结果
6. 可选：发送ScreanCap-Query消息获取UE截屏

**输出验证**：
- **AppList-Response消息**：
  - Message Type: 0x22
  - Fields: app_list (应用信息数组)

- **AppInstall-Response消息**：
  - Message Type: 0x24
  - Fields: result (安装结果状态)

- **ScreanCap-Response消息**：
  - Message Type: 0x26
  - Fields: image_data (截屏图片二进制数据)

**验证要点**：
- App列表查询功能正常
- 应用安装流程完整（APK直装/脚本安装）
- 截屏功能返回有效的图片数据
- 错误处理和超时机制正确

### 2.6 脚本更新流程（IT-06）

**测试目标**：验证拨测脚本的远程更新和部署功能

**输入数据**：
- **ScriptUpdate-Notify消息**：
  - Message Type: 0x31
  - Fields: script_name, version, file_data (脚本文件二进制), crc

**测试步骤**：
1. 基于IT-01完成认证，保持WebSocket连接
2. 准备新的拨测脚本文件和版本信息
3. 发送ScriptUpdate-Notify消息推送脚本更新
4. 验证收到ScriptUpdate-Ack消息确认更新结果
5. 可选：验证脚本版本更新到数据库

**输出验证**：
- **ScriptUpdate-Ack消息**：
  - Message Type: 0x32
  - Fields: script_name, version, result (更新结果)

**验证要点**：
- 脚本文件正确传输和存储
- CRC校验通过
- 版本管理正确
- 更新确认机制可靠

### 2.7 北向API测试（IT-07）

**测试目标**：验证REST API接口的查询和管理功能

**输入数据**：
- **GET /api/executors**：查询执行机列表
- **POST /api/executors/refresh**：刷新执行机信息

**测试步骤**：
1. 确保有执行机完成注册并在线
2. 调用GET接口查询执行机列表
3. 验证返回正确的执行机信息（name、ip、status、lastOnlineTime等）
4. 调用POST接口触发信息刷新
5. 验证刷新操作触发WebSocket消息发送

**输出验证**：
- **执行机列表响应**：
  - HTTP 200状态码
  - 包含执行机基本信息和UE数量
  - 敏感信息已过滤（不返回token）

- **刷新响应**：
  - HTTP 200/202状态码
  - 触发内部状态查询流程

**验证要点**：
- REST API接口格式正确
- 数据安全过滤正常
- 分页和查询参数支持
- 错误响应处理正确

**测试目标**：验证Agent主动注销和会话清理功能

- **DeRegister-Request消息**：

**测试步骤**：
1. 基于IT-01完成认证，建立连接
2. 发送DeRegister-Request消息主动注销
3. 验证收到DeRegister-Ack确认消息
4. 验证数据库状态更新为OFFLINE
5. 验证会话绑定被清理

**输出验证**：
- **DeRegister-Ack消息**：
  - Message Type: 0x06
  - Fields: result (注销结果)

- **数据库状态**：
  - executor.status: 0 (OFFLINE)
  - 会话绑定关系清除

**验证要点**：
- 主动注销流程完整
- 资源清理彻底
- 重复注销处理正确
