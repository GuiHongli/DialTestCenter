# JSR 356 WebSocket 改造方案

## 1. 改造目标

将执行机管理模块从 Spring WebSocket 迁移到 JSR 356 标准实现，确保：
- ✅ **WebSocket 功能完全不变**
- ✅ **消息协议完全兼容**
- ✅ **业务逻辑无需修改**
- ✅ **仅依赖 spring-boot-starter-web**

---

## 2. 核心变更对比

### 2.1 依赖变更

| 项目 | Spring WebSocket | JSR 356 |
|-----|-----------------|---------|
| Maven 依赖 | `spring-boot-starter-websocket` | `spring-boot-starter-web`（内置支持） |
| Java 包 | `org.springframework.web.socket.*` | `javax.websocket.*` |

**操作**：删除 `pom.xml` 中的 `spring-boot-starter-websocket` 依赖

### 2.2 注解和接口变更

| 功能 | Spring WebSocket | JSR 356 |
|-----|-----------------|---------|
| 端点声明 | 继承 `TextWebSocketHandler` | `@ServerEndpoint("/path")` 注解 |
| 连接建立 | `afterConnectionEstablished()` | `@OnOpen` |
| 接收消息 | `handleTextMessage()` | `@OnMessage` |
| 连接关闭 | `afterConnectionClosed()` | `@OnClose` |
| 错误处理 | `handleTransportError()` | `@OnError` |
| 会话对象 | `WebSocketSession` | `Session` (javax.websocket.Session) |

### 2.3 配置方式变更

| 项目 | Spring WebSocket | JSR 356 |
|-----|-----------------|---------|
| 配置类 | `@EnableWebSocket` + `WebSocketConfigurer` | `ServerEndpointExporter` Bean |
| 端点注册 | `registry.addHandler()` | 自动扫描 `@ServerEndpoint` |

## 4. 关键技术点

### 4.1 Spring Bean 注入问题

**问题**：JSR 356 的 `@ServerEndpoint` 端点不是标准 Spring Bean，每个连接会创建新实例

**解决方案**：使用静态字段 + setter 注入

```java
@Component
@ServerEndpoint("/wss/agents")
public class ExecutorWebsocketEndpoint {
    
    // 使用静态字段存储 Spring Bean
    private static WebSocketSessionRegistry sessionRegistry;
    private static WssMessageDispatcher dispatcher;
    
    // 通过 setter 注入（仅首次调用）
    @Autowired
    public void setSessionRegistry(WebSocketSessionRegistry registry) {
        ExecutorWebsocketEndpoint.sessionRegistry = registry;
    }
    
    @Autowired
    public void setDispatcher(WssMessageDispatcher dispatcher) {
        ExecutorWebsocketEndpoint.dispatcher = dispatcher;
    }
}
```

### 4.2 消息发送 API 差异

| 操作 | Spring WebSocket | JSR 356 |
|-----|-----------------|---------|
| 发送文本 | `session.sendMessage(new TextMessage(text))` | `session.getBasicRemote().sendText(text)` |
| 同步发送 | `sendMessage()` | `getBasicRemote().sendText()` |
| 异步发送 | 需要额外配置 | `getAsyncRemote().sendText()` |

### 4.3 会话管理保持一致

| 功能 | 实现方式 |
|-----|---------|
| Session ID | `session.getId()` 两者完全一致 |
| 会话存活检查 | `session.isOpen()` 两者完全一致 |
| 会话属性 | `session.getUserProperties()` 可以存储自定义数据 |

## 10. 总结

### 改造核心要点

1. **依赖变更**：删除 `spring-boot-starter-websocket`，依赖内置 Tomcat WebSocket 支持
2. **注解变更**：从 Spring WebSocket API 改为 JSR 356 标准注解
3. **类型变更**：`WebSocketSession` → `javax.websocket.Session`
4. **配置变更**：使用 `ServerEndpointExporter` 自动注册端点

### 功能一致性保证

- ✅ WebSocket 端点路径不变
- ✅ 消息协议格式不变  
- ✅ 业务逻辑代码不变
- ✅ 会话生命周期管理不变
- ✅ 所有消息类型处理不变
- ✅ CHAP 认证流程不变
- ✅ 客户端代码无需修改

### 优势

1. **标准化**：使用 Java EE 标准 API
2. **轻量化**：减少 Spring 依赖
3. **性能**：使用容器原生实现，可能性能更好
4. **兼容性**：符合项目约束（仅使用 spring-boot-starter-web）
