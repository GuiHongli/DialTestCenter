> 适用范围：本计划用于将《执行机管理软件实现设计.md》中 V2 设计落地到 DialTestCenter 工程（后端 Spring Boot、前端 React、PostgreSQL）。计划涵盖代码结构、数据库变更、实现步骤、测试与验收、风险与排期等。

- **范围**：
  - 后端：`com.dialtest.center.executormanagement` 模块新增（Controller/WSS/Service/DAO/Entity/DTO）。
  - 数据库：新增/变更三张表（`agent_user`、`executor`、`ue`）及索引、约束。
  - 前端（如有管理页）：执行机列表与详情查询的对接（北向 API）。
  - 文档与测试：按工程规则生成 YAML API 文档与 JUnit4+Mockito 单元测试（实体/服务/控制器）。

### 4. 数据库与迁移（database/ 目录）

- 表设计（与设计文档一致）：
  - `agent_user(id, username UNIQUE, password(NTLM hash), last_login_time)`
  - `executor(name PK, ip, token, proxy, description, status, last_online_time)`
  - `ue(msisdn PK, executor_name FK->executor.name, vendor, os, info JSON, task_info TEXT)`
- 建议迁移 SQL（示例片段）：
  - 创建表与索引（PostgreSQL）：
    - `CREATE TABLE agent_user (...)`，索引 `idx_agent_user_username`（UNIQUE）。
    - `CREATE TABLE executor (...)`，索引 `idx_executor_status_last_online_time`。
    - `CREATE TABLE ue (...)`，索引 `idx_ue_executor_name`、`idx_ue_vendor`。
  - 字段 `info` 使用 `JSONB`（若当前策略统一 TEXT，可先 TEXT，后续迁移 JSONB）。
- 约束：
  - `executor.status` 小整数枚举（0:OFFLINE,1:ONLINE,2:INVALID）。
  - `ue.executor_name` 外键级联（删除执行机时可选置空或级联删除，按运营要求选型）。

### 5. 实现步骤详解（后端）

5.1 实体与 DAO
- 新增 `AgentUserEntity`、`ExecutorEntity`、`UeEntity`，注解：`@Entity`、`@Table`，字段映射与约束；重写 `equals/hashCode/toString`。
- 新增 `AgentUserDao/ExecutorDao/UeDao` 继承 `JpaRepository`。仅提供必要派生查询方法（如 `findByUsername`、`findByName`、`findByExecutorName` 等）。

5.2 WSS 网关与消息分发
- 依赖：`spring-boot-starter-websocket` 与 Jackson。
- 端点：`/wss/agents`，支持 WSS。注册 `WebSocketHandler` 或使用 `@ServerEndpoint`（结合 Spring 管理）。
- 会话管理：
  - 维护 `sessionId -> Session`、`sessionId -> executorName/token/challenge` 的并发映射。
  - `onOpen`：记录连接源 IP、时间戳。
  - `onClose`：通知 `ExecutorMgmtService.handleExecutorDisconnect(sessionId)`。
- 消息模型：统一 JSON 包装 `{message_type, data}`。
- `WssMessageDispatcher`：
  - 解析 `message_type`，用 Jackson 绑定 `data` 到具体 DTO。
  - 路由：`register_request/register_auth` -> `AuthSessionService`；`heartbeat_status` -> `ExecutorMgmtService`；`task_status_update` -> `TaskInterfaceService`；其余进入 `default` 分支记录警告并返回错误响应。

5.3 认证与会话（CHAP）
- 阶段：`register_request` -> `register_challenge` -> `register_auth` -> `register_ack`。
- `register_request`：生成 16 字节随机 `challenge`（安全随机数），缓存 `sessionId->challenge`，通过网关发回 `register_challenge`。
- `register_auth`：
  - 查 `AgentUserDao.findByUsername` 得到存储的 NTLM Hash。
  - 计算 `check = MD5(dbNtlmHash + challenge)`，与客户端 `response` 对比。
  - 通过：生成 `token`（UUID 或 JWT 的 opaque 方案），绑定 `sessionId->executorName/token`，落库 `ExecutorDao.saveOrUpdate(name, token, ONLINE)`；失败：发送 `register_ack` 失败。
- 安全要点：
  - Challenge 设定 TTL（如 2 分钟），使用后即作废。
  - Token 仅在内网使用，必要时设置过期与刷新策略。

5.4 执行机服务（心跳/信息/离线）
- `handleHeartbeatStatus(HeartbeatStatus)`：
  - `ExecutorDao.updateStatus(name, ONLINE, now())`。
  - `UeDao.batchUpsert(ue_list)`：序列化丰富的 UE 状态到 `info` JSON 字段；考虑批量写优化（分批 100～500）。
- 连接关闭处理：`handleExecutorDisconnect(sessionId)` -> 通过会话绑定找 `executorName` -> `ExecutorDao.updateStatus(executorName, OFFLINE)`。
- 可选：定时任务扫描心跳超时（3 个周期未报）设为 OFFLINE；超 10 天老化。

5.5 任务接口服务
- 下发：`dispatchTaskToAgent(task)` -> 组装 `task_assign`（包含 `script_name/script_version`）-> `WssMessageSender.sendTaskAssign(sessionId, payload)`。
- 上报：`handleTaskStatusUpdate(TaskStatusUpdate)` -> 事件/回调通知上层任务管理（按现有体系对接）。
- 扩展：脚本更新（`script_update_notify/script_update_ack`）、App 安装（`app_install/app_install_result`）同理通过发送器实现。

5.6 北向 REST API
- `ExecutorController`（示例）：
  - `GET /api/v1/executors`：分页/过滤（状态、关键字）。
  - `POST /api/v1/executors/refresh`：触发向 Agent 拉取详情（`update_executor_info`）。
- 要求：
  - 遵循 REST 与异常/日志/Javadoc 规则；返回/入参使用 OpenAPI 生成 model（或与之等价 DTO + 映射）。
  - 生成 YAML 文档，放置于约定目录，并纳入构建流水线。

5.7 配置与常量
- `application.yaml`：
  - WSS 端点路径、心跳周期/超时、challenge TTL、token TTL、批量写入大小等。
  - 通过 `@ConfigurationProperties` 暴露配置，避免硬编码。

5.8 日志与异常
- 统一使用工程日志门面；入口/出口、鉴权失败、分发失败、DB 异常、解析异常必须有结构化日志。
- 异常处理：Controller 层使用全局异常处理器返回标准错误；Service 层抛出有意义的自定义异常，不吞异常。

5.9 性能与并发
- 并发 Map 存储会话；谨慎同步；避免长时间持有锁。
- 批量 DB 写入、按需字段更新；热点路径打点埋点（QPS、失败率）。

### 10. 验收标准（关键用例）

- CHAP 流程：正确返回 `register_challenge`，`register_auth` 校验通过生成 `token` 并落库，失败返回原因。
- 心跳：30s 周期心跳将执行机置为 ONLINE，更新 `last_online_time`；UE 详细信息批量更新正确。
- 断连：`onClose` 后执行机状态置为 OFFLINE。
- 任务：`task_assign` 可根据 `script_name/script_version` 下发，Agent 上报的 `task_status_update` 可被接收并转发到上层模块。
- 脚本/App：`script_update_notify/app_install` 能发送并接收结果。
- 北向 API：列表与刷新接口工作正常，YAML 文档完整。
- 日志/异常：关键路径有结构化日志，异常按规范返回。

### 11. 风险与缓解

- WSS 大量连接与并发：
  - 缓解：连接数上限与资源监控、异步发送、批量更新、线程池参数化。
- 批量 DB 写性能：
  - 缓解：分批提交、必要索引、减少无关字段更新。
- 认证安全性：
  - 缓解：Challenge TTL、一次性使用、强随机源、Token 过期策略、日志脱敏。

### 13. 本地运行与联调建议

- 后端：`backend/` 启动 `DialTestCenterApplication`，开启 WSS 端点 `/wss/agents`。
- 模拟 Agent：使用 `websocat` 或简单 Python/WebSocket 客户端脚本，按设计文档消息顺序发送 JSON 验证流程。
- 验证步骤：
  1. `register_request` -> 收到 `register_challenge`。
  2. 计算 `response` 后 `register_auth` -> 收到 `register_ack`（含 token）。
  3. 周期 `heartbeat_status` -> DB 中 ONLINE 与 UE 信息更新。
  4. 服务端触发 `task_assign` -> 客户端上报 `task_status_update`。
