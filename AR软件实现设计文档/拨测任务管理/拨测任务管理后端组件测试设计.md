# 拨测任务管理后端组件集成测试设计

## 1. 概述

本文档定义了拨测任务管理组件（TaskManagement）的集成测试用例，覆盖任务管理、模板管理、异步回调等核心功能。集成测试在完整的Spring Boot环境中执行，包含真实数据库交互。

### 1.1 测试范围

- **TaskController** - 任务启动、查询、停止
- **TemplateController** - 模板CRUD操作
- **CallbackController** - 异步回调处理
- **Service层** - 业务逻辑验证
- **DAO层** - 数据持久化验证
- **数据库** - 表结构和数据完整性

### 1.2 测试环境

| 组件 | 配置 |
|------|------|
| 框架 | Spring Boot + JUnit 4 + Mockito |
| 数据库 | 嵌入式PostgreSQL（测试环境） |
| Web容器 | 内嵌Tomcat |
| 测试工具 | RestAssured + Spring Test |

### 2.7 场景 SC-07：主流程全链路贯通（冒烟）

**场景描述：** 从人工启动验证开始，按“全成功路径”贯通所有关键状态：START_VALIDATION → START_TRAINING_DIALING → START_MODEL_TRAIN → START_MODEL_REPLAY → START_GRAY_VALIDATION → START_FULL_REPLAY → START_WHITELIST → START_FULL_RELEASE → FINAL。用于验证状态机配置与各`Action`/子任务衔接是否正确。

#### 2.7.1 测试用例 TC-07-001：全成功路径贯通到 FINAL

**用例编号：** TC-07-001  
**优先级：** P0  
**预期结果：** 任务最终`status='COMPLETED'`、`result='SUCCESS'`、`context.step='FINAL'`，且中间每一步状态切换符合状态流转表。

**前置条件：**
- 环境初始化完成；
- 异步步骤可通过`/api/callbacks/notify`触发；
- 如有桩件/测试开关，使各`Action`在秒级返回结果。

1) 人工启动（验证场景）

```java
  "targetUes": ["ue_001", "ue_002"]
}
```
期望：202；记录`MAIN_ID`；`context.step="START_VALIDATION"`。

2) 验证结束（存在失败 → 进入训练拨测）
- 等待或桩件完成；断言：`context.step="START_TRAINING_DIALING"`。

3) 训练拨测达标（→ 模型训练）
- 等待完成；断言：`context.step="START_MODEL_TRAIN"`，含`async_job_id`。

4) 模型训练回调 SUCCESS（→ 样本回放）
```java

  "status": "SUCCESS",

}
```
断言：`context.step="START_MODEL_REPLAY"`，并记录模型标识。

5) 样本回放达标（→ 灰度验证）
- 等待完成；断言：`context.step="START_GRAY_VALIDATION"`。

6) 灰度验证“能阻断”（→ 全量回放）
- 等待完成；断言：`context.step="START_FULL_REPLAY"`。

7) 全量回放达标（→ 白名单验证）
- 等待完成；断言：`context.step="START_WHITELIST"`。

8) 白名单验证无误伤（→ 全量发布）
- 等待完成；断言：`context.step="START_FULL_RELEASE"`。

9) 全量发布成功（→ FINAL）
- 等待完成；最终断言：
  - `context.step='FINAL'`
  - `status='COMPLETED'`
  - `result='SUCCESS'`
  - `endTime` 非空

|---------|---------|---------|
