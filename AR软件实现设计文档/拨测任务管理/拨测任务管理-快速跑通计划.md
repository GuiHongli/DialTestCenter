## 拨测任务管理 - 快速跑通计划（MVP）

### 目标与范围（1-2 天）
- **目标**: 
  - 在后端中以最小实现跑通“人工启动任务 → 状态机执行 → 异步回调 → 状态流转 → 查询状态”的基本闭环，便于演示与迭代。
  - 基于现有前端框架新增一个“任务编排与进展”页面，可在前端发起任务、查看启动流程与实时进展。
- **范围**: 仅实现文档中的核心链路与关键接口；持久化按最小表结构落地；动作逻辑以可控的假实现或异步回调模拟为主；前端新增 1 个最小可用页面对接上述 3 个接口并提供轮询展示。

### 成果物
- 可启动的后端应用（本仓 `dialingtest-service`）。
- 两张最小表（Task/Template）与初始化 SQL。
- 三个接口可用：`POST /dialingtest/tasks/start`、`GET /dialingtest/tasks/{id}`、`POST /dialingtest/callbacks/notify`。
- 状态机最小流转与持久化（含监听持久化）。
- 前端新增页面：`/task-management`，可“下发任务/查看流程进展”。
- 自测命令与验收清单。

## 五、自测命令（PowerShell）

### 1) 启动一个拨测任务（默认让校验失败，从而进入训练分支）
```powershell
$body = @{ business_type = "VPN_BLOCK"; scenario = "TRAINING"; forceResult = "FAILED" } | ConvertTo-Json
Invoke-RestMethod -Method Post -Uri "http://127.0.0.1:8080/dialingtest/tasks/start" -ContentType "application/json" -Body $body
# 响应示例：{ id: 101, status: "RUNNING", context: { step: "START_MODEL_TRAIN", async_job_id: "" } }
```

### 2) 查询任务状态
```powershell
Invoke-RestMethod -Method Get -Uri "http://127.0.0.1:8080/dialingtest/tasks/101"
```

### 3) 发送异步回调（模拟“训练完成”）
```powershell
$cb = @{ async_job_id = "job-101"; status = "SUCCESS" } | ConvertTo-Json
Invoke-RestMethod -Method Post -Uri "http://127.0.0.1:8080/dialingtest/callbacks/notify" -ContentType "application/json" -Body $cb
```

### 4) 再次查询，验证进入 FINAL
```powershell
Invoke-RestMethod -Method Get -Uri "http://127.0.0.1:8080/dialingtest/tasks/101"
# 预期：status=COMPLETED/FAILED（由回调决定），context.step="FINAL"
```

## 六、验收清单（通过即完成 MVP）
- 启动接口可创建主任务，数据库 `task` 表插入成功，`status=RUNNING`，`context.step=START_VALIDATION 或 START_MODEL_TRAIN`。
- 状态机进入校验动作；当 `forceResult=FAILED` 时写入 `START_MODEL_TRAIN` 并等待回调。
- 回调接口可触发状态机继续流转，最终写回 `FINAL`；`status` 与 `result` 与回调一致。
- 查询接口能返回 `context.step` 的实时值。

## 十一、前端页面（基于现有框架）

### 1) 页面目标
- 在前端新增一个“任务编排与进展”页面（路径：`/task-management`）。
- 支持：
  - 任务下发（表单发起 `POST /dialingtest/tasks/start`）。
  - 展示某个任务的实时进展（轮询 `GET /dialingtest/tasks/{id}`）。
  - 展示任务列表的当前状态（可选，最小版先展示最近一次任务和历史若干条）。

### 2) 前端文件与改动点
```
frontend/src/
├── pages/
│   └── TaskManagement.jsx                # 新增页面
├── services/
│   └── taskManagementService.js          # 新增服务封装（startTask/getTask/listTasks）
├── App.jsx                                # 路由新增：/task-management
└── components/Layout.jsx                  # 侧边菜单新增“任务编排”入口
```

### 3) 服务封装（`services/taskManagementService.js`）
- `startTask(payload)` → `POST /dialingtest/tasks/start`
- `getTask(taskId)` → `GET /dialingtest/tasks/{id}`
- `listTasks(params)`（可选，后续迭代） → `GET /dialingtest/tasks`

说明：沿用现有 `utils/apiUtils.js` 的封装与错误处理风格。

### 4) 路由和菜单
- `App.jsx` 中新增：`<Route path="/task-management" component={TaskManagementPage} />`
- `components/Layout.jsx` 的 `menuItems` 中，在 `operation` 分组下新增：
  - key: `/task-management`，icon: `ToolOutlined`，label: i18n: `navigation.taskManagement`

### 5) 页面功能（MVP）
- 顶部表单（AntD Form）：
  - 字段：`business_type`、`scenario`、`script_names`（多选/输入）、`target_ues`（可选）、`forceResult`（SUCCESS/FAILED，用于演示流程分支）。
  - 点击“开始任务”调用 `startTask`，成功后记录 `taskId` 并开始轮询。
- 进展展示区：
  - 使用 AntD `Steps` 或 `Timeline` 展示 `context.step` 的当前节点，并以颜色/状态标记（running/finished/error）。
  - 轮询间隔 3s：若 `status === 'RUNNING'` 则继续轮询；进入 `FINAL` 后停止轮询。
- 任务列表（可选最小版）：
  - 表格显示 `id/start_time/status/result/context.step`。
  - 点击某行“查看进展”可切换当前进展展示的 `taskId`。

### 6) i18n
- 在 `src/locales/zh.json` 与 `src/locales/en.json` 中新增：
  - `navigation.taskManagement`
  - `task.start`、`task.running`、`task.final`、`task.result.success`、`task.result.failed`
  - 表单与列名相关文案键值。

### 7) UI 交互与状态映射
- 将 `TaskState` 到 Steps 索引的映射固化在前端常量中（最小三步：VALIDATION → TRAIN → FINAL）。
- `status` 字段用于顶部总体状态展示，`context.step` 用于步骤定位；当 `result` 为 `FAILED` 时，标记错误态并提示。

### 8) 前端运行
```bash
cd frontend
npm install
npm run start
```

### 9) 前端验收清单
- 左侧菜单出现“任务编排”，可进入 `/task-management`。
- 表单可以提交并得到 TaskId，页面开始轮询并展示步骤流转。
- 当通过回调把任务置为 SUCCESS/FAILED 时，页面步骤与状态同步更新并停止轮询。
- 刷新页面后仍可通过最近任务列表选择并查看进展。
